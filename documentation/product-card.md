# Документация: Универсальная карточка товара (Product Card)

Данная документация описывает работу компонентов внутри карточки товара (`.product-card`) на сайте. Логика реализована в модуле `js/modules/product-card.js`. Карточка является SSR-френдли, то есть большинство начальных состояний и расчетных данных (цены) передаются напрямую в HTML во время генерации страницы, а JavaScript выступает исключительно в роли клиентского улучшателя (пересчет при кликах, открытия дропдаунов и т.д.).

---

## 1. Блок дополнительных характеристик (Specs Toggle)

В некоторых карточках список характеристик может быть очень длинным. Для скрытия длинных списков применяется логика «Показать ещё» / «Свернуть».

*   **Контейнер:** `.product-card__specs`
*   **Элементы списка:** `.product-card-specs__item`
*   **Кнопка переключения:** `.product-card__more`

При количестве элементов 2 или меньше кнопка «Показать ещё» автоматически скрывается. При клике на кнопку родительский блок получает класс `.is-expanded` (который раскрывает контент через CSS), а текст кнопки меняется на «Свернуть».

---

## 2. Выпадающие списки (Dropdowns)

В карточке могут присутствовать универсальные дропдауны для выбора опций (например: Цвет, Размер, Порода дерева).

Они используют общие классы:
*   **Контейнер:** `.product-card-dropdown`
*   **Кнопка-триггер:** `.product-card-dropdown__trigger` (с атрибутами доступности `aria-expanded`, `aria-controls`)
*   **Значение:** `.product-card-dropdown__value` (элемент текста, который меняется при выборе)
*   **Меню (список):** `.product-card-dropdown__menu`
*   **Элемент меню (опция):** `.product-card-dropdown__option` (в атрибуте `data-value` или самом текстовом содержимом хранится результат выбора)

### Поведение:
*   Скрипт автоматически находит все дропдауны и проставляет им необходимые атрибуты для доступности (айдишники для `aria-controls` генерируются на лету).
*   При клике на триггер открывается меню (вешается класс `.is-open` на главный контейнер).
*   Приликe на опцию, текст триггера меняется на выбранный, элементу меню добавляется класс `.is-selected`, и дропдаун скрывается.
*   При выборе новой опции триггерится кастомное JS-событие `pc:dropdown-change`, которое можно отлавливать на уровне всей страницы для дополнительной аналитики или бизнес-логики.

## 3. Расчет итоговой цены и Счетчики в ценовых рядах (Price Rows)

В карточке могут присутствовать различные единицы измерения (штуки, кубометры, погонные метры и т.д.), которые вынесены в так называемые «ценовые ряды» (`[data-pc-price-row]`). Скрипт умеет пересчитывать общую стоимость карточки на основе состояния счетчиков.

### DOM-контракт для ценовых рядов:

*   **Сам ряд:** `[data-pc-price-row]`
*   **Базовые цены, передаваемые сервером:** 
    *   `data-unit-price` (текущая цена за условную единицу товара в этом ряду)
    *   `data-unit-old-price` (старая цена, если есть скидка)
*   **Блок счетчика:** `[data-pc-counter]`
    *   Кнопка «Минус» / «Удалить»: `[data-pc-counter-dec]`
    *   Поле ввода количества: `[data-pc-counter-input]` (содержит текущее значение `value`)
    *   Кнопка «Плюс»: `[data-pc-counter-inc]`
*   **Рендер итоговой суммы в карточке:** `[data-pc-total-price]` и `[data-pc-total-old-price]` (располагаются где-то в футере карточки)

### Логика расчета (Как это считается):

1. **Инициализация:** Скрипт парсит цены `data-unit-price` из HTML. Это позволяет защититься от мусора в верстке (удаляются пробелы и символы валют, строка переводится в чистое число).
2. **Формула:** Для карточки с любым количеством независимых ценовых рядов итоговая сумма считается по формуле: `ИТОГ = Σ (количество_в_ряду_i × базовая_цена_ряда_i)`.
3. **Обновление суммы:** 
   При любом клике по счетчику или при вводе в инпут скрипт пробегается по всем рядам `[data-pc-price-row]`, умножает их количество на значение единицы товара, суммирует все вместе и выводит в `[data-pc-total-price]`.
4. **Старая цена:** Блок старой цены (`[data-pc-total-old-price]`) отображается *только* в том случае, если расчетная итоговая старая сумма строго больше 0 и больше новой суммы. Если она равна 0, блок скрывается через класс `.is-hidden`.

### Поведение левой кнопки счетчика (Уменьшение):

Кнопка декремента (`[data-pc-counter-dec]`) меняет свой внешний вид и функции в зависимости от текущего количества:
*   При `qty = 0`: Кнопка становится скрытой. Пользователь видит только «плюс» и поле ввода.
*   При `qty = 1`: Кнопка принимает вид корзины (вешается класс `.is-cart`). По клику на неё количество сбрасывается в 0, и она снова скрывается.
*   При `qty >= 2`: Кнопка работает как стандартный «минус» (вешается класс `.is-minus`). По клику отнимает `1` от количества.

## 4. Галерея карточки в каталоге

Галерея карточки каталога инициализируется модулем `js/modules/sliders.js` на корневом контейнере `.js-product-card-slider` и использует SlickSlider.

DOM-контракт:
- `.product-card__gallery` - внешний контейнер галереи
- `.product-card__slider.js-product-card-slider` - корневой элемент SlickSlider
- `.product-card__slide` - один слайд
- `.product-card__image-frame` - фрейм изображения c постоянной пропорцией `3 / 4`
- `.product-card__image` - изображение с `width: 100%`, `height: 100%`, `object-fit: contain`
- `.product-card__pagination` - контейнер для Slick dots

Поведение:
- на desktop при движении мыши по галерее активный слайд меняется по hover-зонам
- при `mouseleave` галерея возвращается на первый слайд
- по `dblclick` на изображении включается zoom с масштабом `3`
- при смене слайда, `mouseleave` и `Escape` zoom сбрасывается
- после AJAX-добавления товаров галерея и логика карточек переинициализируются через событие `catalog:products-appended`
