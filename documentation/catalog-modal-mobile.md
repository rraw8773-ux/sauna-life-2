# Документация: Мобильное полноэкранное меню каталога (Mobile Catalog Menu)

В данном документе описана архитектура и логика работы полноэкранного мобильного меню каталога, которое открывается по кнопке «Каталог» в нижней мобильной навигационной панели.

## 1. Обзор функционала

- **Fullscreen-оверлей**, который открывается поверх контента, но **строго под шапкой сайта (header)**.
- **Вкладки (Tabs):** Каталог, Услуги, Контакты.
- **Drill-down навигация (Каталог):** Неограниченная вложенность категорий с анимацией скольжения экранов (как в нативных приложениях iOS/Android).
- **Свайп вниз для закрытия:** Поддерживается закрытие меню жестом «свайп вниз» за «шапку» меню или специальный drag handle.
- **Отзывчивость:** Меню учитывает безопасные зоны смартфонов (iOS notch / `safe-area-inset-bottom`) и сосуществует с нижней панелью навигации (`mobile-nav`).
- **Синхронизация данных:** Данные для вкладки «Каталог» и «Услуги» частично парсятся напрямую из DOM десктопного модального окна каталога (`#catalog-modal`), чтобы избежать дублирования HTML-кода. Для сложных категорий (например, печи) прописана кастомная структура в JS.

---

## 2. Структура файлов

- **HTML:** Вставка `div#mobile-catalog-menu` перед `nav.mobile-nav` (см. `catalog.html`). Триггер открытия — кнопка `button#mobile-catalog-btn`.
- **CSS:** `css/modules/mobile-catalog-menu.css` (подключен в `global.css`).
- **JS:** `js/modules/mobile-catalog-menu.js` (подключен и инициализируется в `main.js`).
- **Утилиты:** Стили скроллбаров вынесены глобально в `css/base/utilities.css`.

---

## 3. CSS и позиционирование (Ключевые особенности)

### 3.1. Позиционирование под Хедером

Хедер сайта имеет свойство `display: contents;` (см. `header.css`). Это означает, что сам элемент `<header>` не имеет физических размеров (его `getBoundingClientRect().bottom` всегда равен `0`).
Для корректного отступа сверху (чтобы меню не перекрывало шапку), JavaScript вычисляет нижнюю границу самого нижнего _видимого_ дочернего элемента хедера (`.header__top`, `.header__middle`, `.header__bottom`) и записывает значение в CSS-переменную `--mcm-top`.

В CSS меню позиционируется следующим образом:

```css
.mcm {
  position: fixed;
  top: var(--mcm-top, 0px);
  left: 0;
  right: 0;
  bottom: 0;
  z-index: 1050; /* Должен быть ниже mobile-nav (1060) */
}
```

### 3.2. Safe Area и Нижняя панель

Так как внизу экрана закреплена `nav.mobile-nav` высотой около 60px, а также существуют системные зоны iOS (notch), у меню задан внутренний отступ снизу:

```css
padding-bottom: calc(60px + env(safe-area-inset-bottom, 0px));
```

Это гарантирует, что списки категорий можно будет доскроллить до конца, и их не перекроет навигационная плашка.

### 3.3. Глобальные скроллбары

Стиль тонких аккуратных скроллбаров (для вебкита и фаерфокса) вынесен в `css/base/utilities.css`, чтобы применяться единообразно не только к меню, но и к другим блокам сайта со скроллом.

## 4. JavaScript Логика (`mobile-catalog-menu.js`)

Основной скрипт выполняет следующие функции:

### 4.1. Парсинг данных (`parseCatalogData` и `parseServicesData`)

- **Базовые категории:** Берутся из левой колонки меню `#catalog-modal`.
- **Подкатегории:** Собираются из соответствующих `catalog-modal__panel`. Из выборки исключаются промо-блоки (по классу `.catalog-modal__promo`) и колонка "Другие услуги" (она парсится отдельно для вкладки "Услуги").
- **Сложная вложенность (Печи):** Для поддержки 3-4 уровней вложенности («Печи для бани», «Дровяные печи» и т.д.) структура захардкожена в функции `getNestedCategoryData()`. При сборке данных JS проверяет, есть ли ID категории в кастомных данных, и если есть — использует их, иначе парсит DOM. Это позволяет создавать сколь угодно глубокую структуру для выбранных разделов.

### 4.2. Механика Drill-Down

Используется стек страниц (Массив `pageStack`).

- Корневая страница рендерится при инициализации.
- При клике на категорию с подкатегориями (имеет `children` в массиве), создается новый `div.mcm__page` со списком подкатегорий.
- **Анимация перехода:** Новой странице присваивается класс `.mcm__page--enter-right` (смещение вправо на 100%), затем он заменяется на `.mcm__page--active`. Текущая страница получает `.mcm__page--exit-left` (смещение влево).
- При нажатии "Назад" анимация проигрывается в обратную сторону, а последняя страница извлекается из стека и удаляется из DOM.

### 4.3. Свайп вниз (Swipe-to-close)

Логика портирована из боковых панелей (offcanvas). Слушатели событий `touchstart`, `touchmove`, `touchend` вешаются на два элемента:

1. Специальный ползунок над шапкой (`.mcm__drag-handle`).
2. Шапка самого меню (`.mcm__header`).

При свайпе вниз меню следует за пальцем (`transform: translateY(deltaY px)`). Отключаются CSS-транзиции для отсутствия задержки. При отпускании пальца вычисляется пройденное расстояние и скорость свайпа. Если они превышают пороговые значения (соответственно `100px` или высокая скорость), меню закрывается, иначе — пружинит обратно.

### 4.4. Клонирование контактов (`cloneContacts`)

Содержимое вкладки "Контакты" не генерируется с нуля. JS просто находит и клонирует существующий блок `.mobile-menu__contacts` из обычного бокового мобильного меню (бургер) и вставляет его в панель `data-panel="contacts"`. Стили наследуются автоматически, обеспечивая визуальное единство.

## 5. Инструкция по редактированию

- **Чтобы добавить новые пункты в базовые категории (1-й и 2-й уровень):** Достаточно изменить HTML в десктопном блоке `#catalog-modal`, скрипт спарсит изменения автоматически.
- **Чтобы изменить глубокую структуру (многоуровневые печи):** Необходимо редактировать объект-заглушку в функции `getNestedCategoryData()` внутри `mobile-catalog-menu.js`. Структура объекта:
  ```json
  [
    {
      "text": "Название пункта",
      "href": "#link",
      "count": "100",
      "children": [ ...вложенные пункты... ]
    }
  ]
  ```
- **Чтобы добавить глобальные стили для скроллов:** Смотрите `css/base/utilities.css`.
